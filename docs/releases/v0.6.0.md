# Trading Copilot 0.6.0

This release closes the gap between research advice and a funded manual ETF
workflow, and repairs the audit's confirmation, duplicate-ledger and backtest
admission defects. It includes the previously unreleased 0.5 main-branch work.

## Behavior changes

- Explicit refusals cannot approve a Review or account fact. Refusal outcomes
  preserve the user's original words. Quoted/conditional statements stay blocked.
- Fee or later external-ID supplements cannot silently count an old fill twice.
  Corrections preserve original events and use optimistic versions.
- Confirmed broker opening holdings initialize quantities without invented
  executions or tax basis. Subsequent fills bind the opening cutoff.
- One-off user-confirmed ETF budget/target-share cards coexist with validated
  strategies. Both use live raw quotes, actual settled USD, costs, shared-account
  locks, explicit Review and fresh preflight. No broker order APIs are shipped.
- QQQI/JEPQ primary distribution evidence feeds trailing payout and raw-NAV
  research, explicit tax/FX scenarios and bounded integer allocation comparisons.
  Hypothetical income maxima are not predictions of future total return.
- Actual reported distribution cash has a separate append-only receipt ledger.
  Pay dates do not prove arrival; receipts never create shares or buying power.
- `doctor` reports multiple independent prerequisites and the stage that resolves
  each. Unused foreign-ledger uncertainty does not stand in for missing USD cash.

## Historical calculation migration

Legacy adoption schema 4 includes initial entry costs, rejects zero-exposure
simulation, and validates full history/OOS session continuity. Old adoption
records remain readable but require fresh validation before new orders. Explicit
gold history waivers remain visible and cannot bypass OOS or actual covered-range
checks. Zero drawdown and repeated-peak duration metrics are corrected.

## Delivery

Canonical Skill and both generated runtimes are synchronized. PEP 723 scripts
ship dependency locks; MCP uses tested v1. Windows contracts complement Linux
Python 3.11/3.12/3.13 CI. Deterministic ZIP timestamps/permissions, private-state
leak checks, checksums and a clean extracted-install probe cover distribution.

Current workflow replay saves fixture/code/Skill/tool hashes and limited actual
core call traces. Synthetic contract scores and independent model paper-scenario
checks are reported separately; neither is a profitability benchmark. No real
model FinanceBench/StockBench investment-accuracy result is claimed.

See [delivery procedure and live acceptance](../DELIVERY.md). Live trading
readiness still depends on the user's running IBKR session, actual entitlements,
settled currency cash and explicit human confirmation. Preflight observes state
without locking the broker; refresh after any material change before submission.
