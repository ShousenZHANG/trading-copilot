# investment-chat Skill 升级合同

日期：2026-10-03。设计基线：`a20da36ae486160cb8acd47fdb7fe25714a6e0cf`。本文件记录产品实施合同；本文件保留设计合同，实际交付与验收见[实现记录](trading-skill-implementation-2026-10-03.md)。代码实现、策略准入、个人账户实时验收与收益效果分别报告。个人配置、持仓、现金、研究输出与账户记录不写入本文件。

## 目标

保留一个 `investment-chat` 对话入口，覆盖「收集市场信息 → 代码计算量化数据 → AI 分析支持与反证 → 输出明确且有时效的研究信号 → 有条件时展示已采纳规则计划 → 人工交易与实际成交对账」。量化信号与投资盈利分别验证。完整账本留在本地，模型使用必要的脱敏摘要。

完整目标是结合当前账户，为长期与波段分别给出明确投资决策；满足账户、行情、规则和风险条件时，必须给出可供人工交易的价格与股数。只有技术观察、新闻摘要或永久停留在 `research_only`，都不算完整升级完成。研究信号是中间交付；数据不足或没有合适机会时，明确等待或不交易同样是有效决策。

canonical 来源为 `.claude/skills/investment-chat/`；`.agents/skills/` 和 `skills/` 由 generator 生成。计算与数据合同放在 `scripts/copilot/`，CLI/MCP 只是共享 facade。

## 明确投资决策的最终验收合同

1. **明确动作**：每个标的给出买入、加仓、减仓、卖出、持有、等待或不交易的用户可读结论，注明长期或波段。展示语义必须映射已实现且经过校验的后端状态；多个研究观点最终合并为一个账户适用结论。
2. **明确价格与数量**：可执行买卖卡必须提供已核验合约、币种、规则计算的限价、整股数量、预计费用、现金占用和交易后敞口；按合约 tick 与数量步长取整并重新校验。明确报价时间、bid/ask、实际收到的行情类型、交易卡有效期，以及拟用订单类型、TIF 和交易时段。限价表示接受的价格边界，不承诺成交。估值目标与历史收盘不能冒充当前可交易价格。
3. **明确触发与退出**：列出何时可执行、什么变化撤销建议、何时刷新。波段按已采用策略展示退出/止损参考、计划风险金额和适用时的目标；长期给出投资逻辑失效与再平衡条件，不默认沿用波段止损。跳空与部分成交后的实际损失可能超过计划风险。
4. **账户约束可验算**：用真实原币现金、结算状态、未成交订单与完整持仓约束数量；总资产不是可用现金。长期与波段共享物理账户但保留用途预算，无借款且不重复分配资金或同一批股份。费用、FX、现金缓冲、集中度、单笔与组合风险同时满足，代码计算的可行数量为零则不交易。
5. **证据可追溯**：每张卡保留快照ID、公式/策略版本、支持理由、最强反证、缺项及失效条件；量化数字可以复算。胜率或预期收益只有在有对应验证数据时才展示，模型 confidence 不作收益概率。
6. **缺口有明确状态**：研究条件满足但缺账户、报价或已采用规则时，说明缺哪项、补齐后调用什么计算；不生成假精确股数。`research_only` 不能被呈现为可执行交易卡。准备度通过后，Skill 自动调用交易计划计算，而非要求用户另问一次才能得到价格和数量。
7. **实际成交闭环**：人工成交后，以确认的成交和费用更新实际账本并重新计算剩余计划；建议、模拟成交和真实成交独立。过期卡、账户变化或新成交必须重新评估，不沿用旧数量。

验收场景至少覆盖：有现金的新买入、已有持仓减仓、长期与波段争用资金、待成交卖单、部分成交、过期/延迟行情、缺现金/缺规则、成本后股数归零，以及没有机会时不交易。场景验证输出合同；策略样本外与前瞻净收益是另一项验收，不能由这些测试代替。

## Skill 运行路径草案：真实交易闭环

核验日期：2026-10-03。下面保留实施前的闭环设计；当前实现状态见实现记录，个人真实账户验收另行完成。流程完整性与净收益效果分别验收，不能称为已经证明的全局最优。

### 策略建立与采用：发生在日常执行之前

1. 研究机会和可检验假设，定义候选池、长期/波段用途、数据基准、进入/退出、组合约束与成本模型。
2. 将规则、阈值、选择/排序逻辑与模型版本冻结；做时间隔离的样本外、成本与执行敏感性评估，并保存失败与无信号结果。前瞻 shadow/paper 只验证其覆盖范围，不等同真实成交或真实盈利。
3. 通过预先设定的验收后，由用户明确采用具体规则和预算版本。没有采用的策略只保留研究结果；日常不反复回测择优、自动换参数或把最新模型观点直接变成策略。策略变更要重新验证并采用。

### 日常研究与一次手动交易

| 步骤 | 实际工作 | 通过条件 / 分支 |
|---|---|---|
| 1. 上下文 | 确认请求、标的和模式；读取本地账本的脱敏摘要、规则采用状态与未完成交易状态 | 总资产不作现金；已有开仓库存需可靠确认；覆盖失败保留 unknown |
| 2. 研究快照 | 收集同一 cutoff 的完成日行情、财报、新闻、宏观及明确基准 | 身份、时间、价基、来源和缺项可追溯；禁止未来信息或指数转交易价格 |
| 3. 研究诊断 | 代码计算量化；AI 解释市场、公司、支持与反证，形成候选和触发/失效条件 | 事实与推断分开；未采用模板不生成订单数字；已采用规则的数字不被模型改写 |
| 4. 执行快照 | 用户准备交易时，刷新 IBKR 只读账户、原币现金、挂单/成交、合约、实际 bid/ask、FX 和费用假设 | 真实收到的行情类型、时段、新鲜度及完整性均通过；有未知则等待。异步账户与行情不是天然原子快照，期间发生资金/成交变化就重新采集 |
| 5. 最终计算 | 用当前执行价格与资金重新计算最终限价、费用、股数、退出参考和交易后风险，合并两模式计划 | 不给旧收盘数量加一个 quote-ready 标签；挂单占用、资金/股份用途冲突与取整后约束均通过；可行数量为零则不交易 |
| 6. 人工 Review | 展示有版本的最终交易卡，绑定账户状态、报价、策略和风险配置，说明计划有效期 | Review 对应这张具体卡；支持/反证与退出条件可见；不同计划不重复分配同一资金或股份 |
| 7. 提交前复核 | 用户准备在券商提交时再次核对报价、资金、挂单/新成交与卡有效期 | 不延长原卡有效期；计划价格/股数/方向/风险或关键依据变化则发布新版并重新 Review；数据失败则等待。只读 Agent 无法锁住券商状态或阻止用户手动提交过期单，用户仍需核对 TWS 最终票据 |
| 8. 人工下单与订单状态 | 用户手动下单；以可核验回报区分未提交、working、部分成交、全部成交、拒绝、待撤销、已撤销及未知 | 建议/Review/提交都不等于成交；交易卡到期不等于券商 DAY/GTC 单已失效；只读接口不可见时保留 unknown 并要求人工核对，不能自动补单 |
| 9. 成交对账与风险重算 | 经用户确认的真实成交写实际账本；关联各部分成交、费用与更正，核对剩余挂单和当前库存 | 去重并区分数量、累计数量与费用；费用未知不填零。仅按确认结果更新可用资金/股份并重新生成剩余计划；保留原事件 |
| 10. 持有与效果复核 | 后续显式分析或准备交易时，检查长期逻辑、波段退出、实际净收益与风险 | 不同持有周期独立评价，共享账户预算；统计 no-trade、未成交、失败与成本，不自动调参追随近期输赢。不由本流程隐式创建定时任务 |

研究结论可能持续数日或更久，具体价格与数量只对当前交易卡有效。没有新快照不能复用旧卡；策略采用与人工 Review 均不是自动下单授权。

### 必须保留的状态约束

- 已采用规则的日收盘计划是研究/再平衡输入；实时执行计划必须在现有价格、实际现金和费用下重算，而不是仅添加行情字段。
- 多张卡对同一账户的竞争计划需合并或拒绝冲突。本地占用记录只管理建议之间的分配，不能锁住 IBKR 账户；未核实是否已提交的卡不能仅凭到期就视为资金已释放。
- 各现金字段必须注明是总余额、已结算余额还是已扣挂单的可用额；只扣尚未反映的占用，不能在券商净可用额上重复减一次同一挂单。币种、资金口径或挂单可见性不明确时不输出精确股数。
- 人工撤单请求仍可能在确认前成交；仅在券商确认与成交核对后调整剩余资金/股份。不因 pending cancel、建议过期或网络断线立即释放占用。
- 成交事件和账户快照要能对齐；旧快照不能覆盖较新成交，不能把事件增量与已含同一成交的快照重复记账。断线恢复先对账再生成新增风险计划。
- 波段必须区分分析中的止损参考与用户实际提交的保护单；保护单缺失或回报未知不能显示“已保护”。止损触发、限价触及或预期收益都不承诺实际成交或最大损失。

官方事实依据：[IBKR 行情类型](https://www.interactivebrokers.com/docs/tws-api/doc/market-data-delayed/introduction)区分 live/frozen/delayed；[价格最小变动](https://www.interactivebrokers.com/docs/tws-api/doc/orders/minimum-price-increment/request-market-rule)依合约/交易所与价格变化；[订单状态](https://www.interactivebrokers.com/docs/tws-api/doc/order-management/order-status/understanding-order-status-message)明确 pending cancel 尚未确认撤销并可能继续成交；[Execution](https://www.interactivebrokers.com/docs/tws-api/ref/execution)为各部分成交提供独立 execId，成交价不含佣金；[CommissionAndFeesReport](https://www.interactivebrokers.com/docs/tws-api/ref/commission-and-fees-report)以 execId 关联币种与费用；[order binding](https://www.interactivebrokers.com/docs/tws-api/doc/orders/modifying-orders)可能取消/重提人工订单，适配器不得为读取状态暗中启用。

新增验收场景：Review 期间发生外部交易、报价更新后股数变化、卡到期但 GTC 单仍 working、撤单待确认期间发生 fill、断线恢复收到旧账户快照、一个计划的资金被另一个模式再次分配、波段只有止损参考但实际保护单未提交。只有上述合同与真实只读能力验收通过，才能报告工作流具备实际交易辅助能力。

## 阶段与完成标准

先完整打通现有数据可支持的 Skill 编排、脱敏摘要、量化诊断及信号/规则计划两层输出；这只是第一阶段。完整目标还必须完成美股个股身份与研究入口、IBKR 只读账户/报价、长期与波段的已采用策略，以及上述人工交易卡合同。它们未验收时，只能报告阶段完成，不能报告整个目标已完成。没有实际 live 连接，不声称账户已同步或报价可实时成交；没有前瞻收益验证，不声称信号有效性已经证明。

最低验证包含：MCP/CLI 经同一公开 service 的行为一致；两 runtime 生成无漂移；旧历史建议仍只读；缺现金/覆盖/规则时不生成伪精确数量；数据失败不能变 sell；复权基准不混用；模型摘要无账户标识/原始流水；数值计算反证；隔离 fixture 不触碰个人数据库；prompt/source 输入不能提升规则权限。
